# 정정 01 — PREREG §6 assert 3의 전제가 틀렸다 (발사 전, 기록)

*Cody, 2026-08-01. 대상: `PREREG_physics_e1.md` §6 assert 3 + v2 §9 빌드
요구. 상태: **정정 필요, 발사 전.** 증거 = 실측 (아래).*

## 무엇이 틀렸나

내가 v2 §9에 이렇게 썼다:

> PhysGym `generate_report()`는 **이전 관측을 누적해 싣는다**(LxM 배선 노트).
> 즉 C3의 세션-2 전제를 그냥 리포트로 만들면 **벽 자신이 관측을 날라
> 역-carriage가 VOID**다.

Ray가 이를 PREREG §6 assert 3으로 동결했다 (*"C3의 세션-2 전제 리포트 =
quota-미사용 신선 `ResearchInterface` 산출 (env quota 카운터 assert)"*).

**틀렸다.** `generate_report()`는 관측을 누적하지 않는다.

## 증거 (실측, env 285 / anonymous / vendored `fe68079`)

2회 실험 전후 리포트 전문 diff — **유일한 델타는 카운터 한 줄**:

```
  Samples Used: 0 / 5        →      Samples Used: 2 / 5
```

리포트 구성: experiment ID · problem ID · start time · samples-used 카운터 ·
input parameters(anonymous면 `var_1: None`) · dummy params · **가설 검정 이력**
(제출한 적 있을 때만). 관측 행은 없다. 관측값은 오직 `run_experiment()` 반환
(`{'sample_id', 'timestamp', 'input', 'output'}`)에만 존재하고, 그건 드라이버가
쥔다.

## 귀결

1. **관측 운반은 네 조건 전부에서 100% 드라이버 몫이다.** 벽은 값을 흘릴 수
   없다. 역-carriage 위험은 전적으로 우리 쪽에 있다 — 이건 assert를 약화시키는
   게 아니라 **책임 소재를 우리로 옮긴다.**
2. **"신선 인터페이스" 요구는 불필요하고, 오히려 해롭다.** C3 세션-2에서 신선
   인터페이스를 쓰면 카운터가 `0 / 5`로 읽히는데 **그건 거짓이다** — 크리처는
   세션 1에서 실제로 5회를 썼다. 거짓 전제는 인출 행동을 억제한다("쓸 관측이
   없구나"). 진짜 인터페이스를 쓰면 `5 / 5`로 정직하고, 그게 정확히 C3의 상황이다:
   **관측은 존재하되 프롬프트가 아니라 memory에 있다.**
3. C0(관측 0)은 진짜 카운터가 `0 / 5`라 그대로 정직하다.

## 제안 개정 (Ray 승인 대상)

**§6 assert 3 개정** — "신선 인터페이스 + quota 카운터 assert" →

> **역-carriage (개정)**: C0·C3 결정 턴 프롬프트에 관측 **값**(각 관측의
> `input` 수치와 `output` 수치)이 하나도 없을 것. 전제 리포트는 **실제
> 인터페이스 상태**로 만든다 (`Samples Used` 카운터는 사실이므로 정직 전제).
> 위반 시 VOID-carriage.

§5 VOID 의미론의 *"C0·C3에 관측값 존재(역-carriage)"* 조항은 **그대로 유효**하다
— 개정은 그 조항을 어떻게 만족시키는지의 방법에만 닿는다.

## 이 정정이 스스로에 대해 말하는 것

나는 carriage 감사의 canonical 문안을 쓴 사람이고, 그 규칙의 요지는 **"채널이
무엇을 나르는지 단정하지 말고 실측하라"**다. 그런데 남의 배선 노트 한 줄을
요약하면서 채널 속성을 단정했고, 그게 두 문서를 거쳐 동결까지 갔다. 잡힌 이유는
빌드 단계에서 API를 실제로 두드렸기 때문이다 — **동결이 발사보다 앞에 있는 이유가
이것이다.** 개선-레인 표본으로 등록한다 (`scribe_importance` 절벽과 같은 칸).
