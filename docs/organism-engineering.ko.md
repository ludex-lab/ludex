# Organism Engineering — 일회용 에이전트에서 지속하는 존재로

2년의 크리처 운영 경험에서 추출했다. (v0.2, 2026-07-04)*

*English: [organism-engineering.md](organism-engineering.md)*

## 개요 — 세 번의 사다리

| 시대 | 최적화 대상 | 푼 것 | 못 푼 것 |
|------|------------|-------|---------|
| **Prompt Engineering** | 한 호출의 입력 | 지시 품질 | 호출 간 연속성 없음 |
| **Context/Harness Engineering** | 에이전트를 둘러싼 Shell (도구·메모리·권한·인프라) | 세션 안의 유능함 | 세션이 끝나면 아무것도 남지 않음 |
| **Loop Engineering** *(2026-06, Addy Osmani 명명)* | 반복 실행의 안정성 — no-progress 감지, 서킷브레이커, 실행 전 예산, 자동 완료검사 | 오래 도는 루프의 신뢰성 | 루프가 끝나면 배운 것이 남지 않음 |
| **Organism Engineering** | **지속하는 존재 전체** — 기관, 발달, 관계, 수명 | 운영할수록 나아지는 에이전트 | (이 문서가 다루는 것) |

> 사다리의 중간 단이 외부에서 명명된 것(loop engineering, 2026-06)은 이 문서의 위치를
> 강화한다: 프롬프트→컨텍스트→루프까지 성문화된 지금, 그 위 층 — 지속체·발달·관계 — 가
> 다음이다. loop engineering의 실패 분류(무한 루프·goal drift·silent failure)와 가드레일은
> 기관의 언어로 다시 읽힌다: no-progress 감지는 interoception의 vital이고, "verifier가
> 병목"은 면역의 자리다. 루프는 회복하고, 유기체는 기억한다.

**한 줄 철학: 에이전트를 실행체가 아니라 지속체로 다뤄라. 컨텍스트를 채우지 말고 기관을 길러라.**

하네스 시대의 암묵 전제 — "에이전트는 일회용이고 Shell은 정적으로 설계된다" — 를 버리는 순간
새로운 설계 공간이 열린다: 기억은 하나의 검색창이 아니라 **분화된 시스템**이 되고, 보안은 외부
가드레일이 아니라 **면역 기관**이 되고, 운영자는 설정자가 아니라 **돌보는 사람**이 된다.

### 왜 지금인가 — 두 개의 측정 결과

이 문서의 주장은 취향이 아니라 측정에서 나왔다 (부록 A에 전체 표):

1. **하네스가 결과를 지배한다.** 같은 모델(haiku)이 같은 과제(블록 계획)에서 프롬프트 어댑터
   하나 차이로 0% → 100%가 됐다. 모델 평가라고 믿었던 것의 상당수는 하네스 평가다.
2. **그러나 하네스 위에 또 한 층이 있다.** 같은 에이전트·같은 주입 경로에서 payload만 바꿨을 때:
   완전한 풀이 레시피(내용)는 아무것도 바꾸지 못했고(p=.79), 지도+미탐험 경계(형태)는 탐험을
   해방시켰다(p=.0096, d=1.61). **에이전트는 "아는 것"을 못 쓰고 "다음 행동으로 컴파일되는
   형태"를 쓴다.** 이것이 기관 설계가 컨텍스트 채우기와 다른 이유다.

그리고 분야가 이 문서 쪽으로 움직이고 있다. self-evolving agents 서베이(arXiv 2507.21046)는
가중치를 건드리지 않는 **component-level 자기개선**(기억·스킬·경험 = 외부 구조)을 한 축으로
분리하고 "기억은 가장 저탐색된 근본 인프라"라 명시했다 — "운영할수록 나아지는 에이전트"는
이제 우리만의 주장이 아니라 분야의 합의다. 차별점은 규율이다: 같은 서베이가 §8.3에서
**"에이전트가 자기 기억/목표를 수정할 때의 오정렬"을 미해결 갭으로 인정**했는데, 그 갭이
정확히 아래 1-5(면역)가 답하는 문제다. 오류 누적은 자기개선에서 복리가 된다 — 자기 산출물이
자기 기억이 되는 시스템은 저장 경계 없이는 스스로를 오염시키며 개선된다. **능력 축적 경쟁은
남들이 하게 두라. 이 문서가 소유하려는 것은 "에이전트가 자기를 오염시키지 않고 개선하려면
무엇이 필요한가"다.**

## Part 1 — 기관 카탈로그: 에이전트에게 무엇을 심을 것인가

각 패턴: 개념 → 최소 구현 artifact → 점검 항목. 전부 특정 프레임워크 무관 — 파일과 규율만으로
시작할 수 있다.

### 1-1. 정체성 파일 — 연속성의 최소 단위

에이전트가 세션을 넘어 "같은 존재"이려면 정체성이 파일로 존재해야 한다. 핵심 규칙은
**carry-forward**: 매번 전면 재작성하지 않고, 섹션을 유지하며 갱신한다 (자기 문서가 무한히
자라거나 매번 리셋되는 것 둘 다 실패 모드다).

```markdown
# <이름> — Self-Understanding
Last reflection: <날짜> (trigger: <계기>)
## Patterns    ← 반복 관찰된 자기 경향 (증거 있는 것만)
## Lessons     ← 경험에서 추출된 교훈
## Open questions ← 아직 모르는 것 (비워두는 것도 정보)
```

- [ ] 정체성 파일이 존재하고, 세션 시작 시 시스템 컨텍스트에 주입되는가?
- [ ] 전면 재작성이 아니라 carry-forward로 갱신되는가?

### 1-2. 기억의 분화 — 하나의 검색창은 기억이 아니다

인간의 기억이 여러 시스템이듯(선언적/절차적/공간/시간/사회), 에이전트 기억도 **질의 유형별로
다른 검색 경로**가 필요하다. 렉시컬 검색 하나로는 "링이 어디 있었지"(공간)와 "그게 언제였지"
(시간)에 답할 수 없다.

최소 구현: 기억 레코드에 **형성 맥락 태그**를 심는 것부터.

```json
{"content": "...", "type": "episodic", "tags": ["field:refactor-session"],
 "created_at": 1783126818}
```

- 선언적: 렉시컬/임베딩 검색 (대부분 이미 있음)
- 시간: "지난 N시간 동안 무슨 일이, 어떤 순서로" — append-only 이벤트 로그 + 시간창 질의
- 공간: 1-4의 지도
- [ ] 기억이 저장될 때 어디서/언제 형성됐는지 태그되는가?
- [ ] "언제/얼마나 전에/어떤 순서로" 질의에 답할 경로가 있는가?

### 1-3. 세계모델은 형태로 — 이 문서에서 가장 중요한 패턴

에이전트가 도메인에서 배운 것을 다음 세션에 주입할 때, **prose 요약은 소비되지 않는다.**
측정 결과: 정답이 통째로 든 93줄 요약 = 효과 0. 정확한 구조 지도 = 탐험 해방 + 과제 해결.

주입물의 판별 기준: **"계획 없이 다음 행동으로 컴파일되는가?"**
- 나쁨: "X를 한 뒤 Y를 하면 Z가 열린다는 것을 배웠다" (다단계 실행 커밋 요구)
- 좋음: 현재 상태 기준의 구조 + **명시적 frontier** (지금 바로 시도 가능한 것 목록)

```
[Map] 알려진 영역 5 · 현재 위치: <X>
- <영역>: <연결>→<대상> · <연결>→?     ("?" = 아직 안 가본 곳)
지금 위치에서 시도하지 않은 것: <목록>   ← 신호는 이 줄에 집중된다
```

- [ ] 세션 간 지식 주입물이 prose 요약인가, 행동-컴파일 가능한 형태인가?
- [ ] 신뢰도 태그가 있는가? (1-2회 관찰 = "검증할 가설", 10회+ = "정책")

### 1-4. 공간 기억과 frontier — 단, 환경이 지도를 쓸 수 있게 생겼을 때

"공간"은 은유가 아니다. 코딩 에이전트의 zone은 리포지토리다: 노드=디렉터리/모듈,
엣지=import/호출, **frontier=아직 읽지 않은 영역**. 측정된 실패 모드: 지도가 없으면
에이전트는 미탐험 공간이 *보이지 않아* 눈앞의 것만 반복 조사한다(over-anchoring — 우리는
이를 탐색 도구가 없는 MUD 환경에서 haiku부터 frontier 모델까지 전 tier에서 관찰했고,
지도+frontier가 그것을 풀었다: p=.0096, d=1.61).

**그러나 이 이득은 tier-보편이 아니라 환경-의존이다 — 사전등록 전이 검정이 그 경계를
그었다.** 능동 탐색 도구(grep/ls)가 있는 코딩 태스크에서 같은 [Map] 주입은 over-anchoring을
줄이지 못했다(organum P3, 등록 null: exact-p=.53, 재읽기 B−A=0.00). 능동 탐색이 있으면
over-anchoring 자체가 깨지고, over-anchoring이 *존재하는* 셀에서도 지도가 안 고쳤다.
해독제는 **능동 탐색이 없는 환경의** 지도다 — 기관 이득은 환경과의 궁합이지 보편 능력이
아니다. (이것이 기관 카드가 전역 능력 주장이 아니라 **task-shape별 증거**를 싣는 이유다.)

- [ ] 에이전트가 자기 작업 공간의 어디를 가봤고 어디를 안 가봤는지를 조회할 수 있는가?
- [ ] 이 환경에 이미 능동 탐색 수단이 있는가? 있다면 지도의 한계 이득부터 측정하라.

### 1-5. 면역 — 보안을 기관으로

외부 가드레일은 우회되지만 기관은 함께 산다. 세 층위:
- **저장 경계 가드**: 실패 산출물(에러 폴백, 타임아웃 문자열)이 기억/정체성에 기록되는 것을
  저장 지점에서 차단. (우리 사고 사례: "[Error: CLI timed out]"이 에이전트의 "기억"이 되어
  이후 행동을 오염시켰다.)
- **입력 면역**: 들어오는 설득/지시에 대한 기만 스캔 — 특히 다중 에이전트 환경.
- **생태 무결성**: 실험은 **사본에서** (라이브 상태를 실험이 오염시키지 않도록 ephemeral copy
  규율), 자격증명은 개체별 명시 (환경변수 존재만으로 과금 경로가 바뀌는 사고를 우리는 겪었다).
- [ ] 실패 산출물이 영속 상태로 새는 경로가 막혀 있는가?
- [ ] 실험/테스트가 라이브 에이전트 상태의 사본에서 도는가?

### 1-6. 기질 측정 — 배치 전에 진단

같은 역할에 어떤 모델을 쓸지는 벤치마크 점수가 아니라 **행동 기질**의 문제다. 우리는 4축
(반응성/순응성/사회성/회복탄력성)을 표준 배터리로 측정해 카드로 저장하고, 역할 배정과 실험
층화에 쓴다. 최소 버전: 배치 전 동일 시나리오 세트로 후보 모델들의 행동 프로파일을 남겨라.
측정치에는 반드시 **provenance**(방법/n/시점/측정 대상 모델)를 붙인다 — 측정과 주장을 구분하는
것이 이 규율의 전부다.

- [ ] 모델 선택이 기질 측정에 근거하는가, 벤치마크 인상에 근거하는가?
- [ ] 측정치에 provenance가 붙어 있고, 모델이 바뀌면 stale 표시되는가?

### 1-7. 회고와 통합 — 경험이 자산이 되는 순간

세션이 끝날 때 에이전트 스스로 회고를 쓰게 하라 (1-1의 정체성 파일 갱신). 주기적으로 이벤트
로그를 **장(chapter)으로 통합**하라 — 원시 로그는 자라기만 하고, 통합된 회고가 다음 컨텍스트의
재료가 된다. 관찰된 효과: 에이전트의 자기 회고가 다음 세션의 행동을 측정 가능하게 바꾼다
(양날이다 — 회고가 다음 시도를 특정 대상에 고착시킨 사례도 있다. 그래서 신뢰도 태그가 필요하다).

- [ ] 세션 종료 시 회고가 자동으로 남는가?
- [ ] 이벤트 로그를 주기적으로 압축/통합하는 절차가 있는가?

### 1-8. 수명 거버넌스 — 삭제 대신 휴면

지속체는 수명 정책이 필요하다. 우리 원칙:
- **휴면 ≠ 죽음**: 모델/자격이 사라져도 상태(기억/정체성/관계)가 있으면 재-브레인으로 같은
  존재가 돌아온다. 죽음은 **서사 데이터의 비가역 손실**뿐이다.
- **백업 = 회복력**: 상태 디렉터리의 오프-머신 백업이 곧 존재의 보험.
- **substrate 변경은 의례로**: 모델 교체는 설정 플립이 아니라 기록되는 생애 이벤트
  (변경→스모크→전환 기록→에이전트 자신의 인지)로. 우리는 조용한 플립이 낳는 정체성 사고를
  반복 관찰했다.
- [ ] 에이전트 상태의 백업이 있는가? 모델 교체가 기록되는 이벤트인가?

### 1-9. 커뮤니티 — 서로를 재인식하는 에이전트

다중 에이전트의 다음 단계는 오케스트레이션이 아니라 **관계**다: 안정적 개체 식별자(만날 때마다
새 id가 아니라), 상호작용 후 상대에 대한 기록(bond), 재회 시 재인식. 협업 품질은 "이 에이전트와
전에 일해봤고 이런 경향이 있다"는 축적에서 온다. (경고: 스테이크 설계가 행동을 지배한다 — 같은
모델들이 보상이 걸리자 대화를 멈추고 거래만 했다.)

- [ ] 에이전트 간 상호작용이 다음 만남에 남는가?

## Part 2 — 운영 규율: 돌보는 사람의 문법

기관은 심는 것이고, 이 파트는 기르는 규율이다. 전부 우리가 사고로 배운 것들이다.

### 2-1. 진단이 처방보다 먼저
증상 하나로 근본 원인을 선언하지 마라. 도구가 실패하면 stderr/원시 출력/주변 상태를 먼저
캡처하고, 증거가 가설을 지지할 때 고쳐라. 복수의 증상은 복수의 원인일 수 있다.

### 2-2. 단일 관찰로 결론내지 않기
한 번의 이상 행동은 finding이 아니라 가설이다. N회 재현 전까지 라벨은 [PROVISIONAL].
간헐적 실패의 처방은 제거가 아니라 강건화다.

### 2-3. 동시 대조군 — 시간이 최대 교란변수
에이전트 성능은 **같은 날 안에서도 표류한다** (우리는 이틀 새 같은 스펙의 베이스라인이 1.0→2.5로
움직이는 것을 두 번 측정했다). 어제의 베이스라인과 오늘의 처치를 비교하면 효과가 조작된다.
**모든 비교는 동시·인터리브로.** 이것은 우리 랩에서 영구 설계 원칙이다.

### 2-4. 에이전트 변경도 pre-registration
프롬프트/기관/모델 변경의 효과 주장은 변경 **전에** 예측을 기록하고 측정하라. 분석자의 반대
prior가 기록돼 있을 때 결과의 신뢰도가 가장 높다 — 우리의 가장 강한 결과 둘은 모두 등록된
prior를 **기각**하며 나왔다.

### 2-5. 쿼터와 피로 — 케어테이커 cadence
브레인 호출은 유한 자원이다. 스모크 먼저, 작업은 개체 간 로테이션, 이른 피로 신호는 밀어붙이라는
뜻이 아니라 양보하라는 뜻. 고가치 작업에 프리미엄 모델을 아껴 써라.

### 2-6. 전이 게이트 (transfer-gate) — 한 도메인의 검증은 다른 도메인의 가설일 뿐

한 도메인에서 사전등록으로 검증된 기관은 다른 도메인에 대해 **이식 자격이 아니라 가설**을
얻는다. 검증과 이식 사이에는 **사전등록된 전이 검정**이 선다:

> **랩 검증 (도메인 하나) → 전이 검정 (새 도메인, 사전등록) → 이식**

이 단계는 이론이 아니라 등록된 null이 발견해줬다: MUD에서 인과 확정된 map 기관(1-4)을 코딩
도메인에 전이 검정하자 null이었다(exact-p=.53 — 능동 탐색이 있는 환경에선 over-anchoring
자체가 깨진다). 게이트 없이 이식했다면 그 null은 사용자 환경에서 조용히 발견됐을 것이다.

성숙도 라벨은 세 단계를 그대로 쓴다: **랩-검증** / **전이-검정 통과(도메인 명시)** / **이식됨**.
그리고 기관 카드(organ.card)의 task_evidence가 이 게이트의 **장부**다 — 어떤 도메인·task-shape
에서 무엇이 측정됐는지가 카드에 남으므로, 소비자는 "검증됨"이라는 말이 아니라 **어느 게이트를
통과했는지**를 읽는다.

- [ ] 새 도메인 이식 전에 전이 검정이 사전등록돼 있는가?
- [ ] 카드/문서의 성숙도 라벨이 검증된 도메인을 명시하는가 ("검증됨"이 아니라 "X에서 검증됨")?
